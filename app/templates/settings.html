Prelander / lander pass-through script — makes sure the source reaches Glitchy
The ad lands on your prelander with ?{{ s.url_param }}=<campaign name>. Put this ONE script on the prelander and the lander (just before </body>). It remembers the parameters and adds them to every outbound link, form and late-injected button, so the click into Glitchy's offer link still carries {{ s.url_param }}= — which Glitchy echoes back as {source}. TikTok adds its click id (ttclid) to the landing URL on every ad click; the script packs it into the source as <campaign name>~<ttclid> so it comes back in the postback too (that's what feeds the Events API below). For JS redirects use location.href = passSource(url).
Update both pages whenever this script changes — the older version forwarded the source only.
Self-check: open a launched campaign's landing URL from the launch result (it shows the exact URL) → click through prelander → lander → the offer link in the address bar must contain {{ s.url_param }}=<name>~<ttclid> (the ~ part appears only when you arrived from a real ad click). If postbacks arrive with an empty source, the Inbox flags it.
Also served at /static/pass-source.js (you can host it on your landers instead of inlining).
