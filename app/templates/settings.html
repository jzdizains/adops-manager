3. Use your ClickFlare campaign URL (or lander with cpid=) as the preset's landing URL — the launcher appends the parameters above. Leave Events API on the next tab off if ClickFlare already sends events to TikTok, or TikTok gets every purchase twice.

So the network's own report is readable: in ClickFlare → Offers → your offer, the Offer URL is what the network sees. source={cf_click_id} is what its postback echoes back, so keep it — but it is an opaque id, so add the campaign in a second sub parameter the network documents, e.g. &aff_sub2={trackingField{{ s.clickflare_field }}}. {trackingField{{ s.clickflare_field }}} is the TikTok campaign name this dashboard launched (the field set in step 1) — {campaign_name} would give ClickFlare's own campaign name instead. Whatever isn't on that URL simply doesn't reach the network: in ClickFlare mode the hop into the offer belongs to ClickFlare, so the lander can't add it. Nothing to add on the page itself: ClickFlare's own script already sends the full lander URL as lpurl.
Lander script — put this ONE script on the prelander and the lander, just before </body>
It remembers the parameters across hops, registers the click with this dashboard (POST {{ track_base or '…' }}/t/click), and adds {{ s.url_param }}=<campaign>~<click id> to every outbound link, form and late-injected button. For JS redirects use location.href = passSource(url). If the dashboard can't be reached it packs the raw ttclid instead, so nothing is lost.
Self-check: click one of your own ads → the offer link in the address bar must end with ~<12 characters>, and the live check above counts the click.
The script also publishes what it found as window.adopsParams (.source .ttclid .clid) and fires a adops:click event once the click id is back — handy for a page's own pixel, e.g. ttq.identify({ external_id: window.adopsParams.ttclid }).
Also served at {{ track_base or '' }}/static/pass-source.js — loading it from there needs no editing when this changes.
